# Core Scripts Reference

Full per-script contract detail for `src/`: JSON shapes, CLI flags, typed
error names, edge cases. Read this file before modifying or calling any script listed here.

**Input-file errors.** A missing, directory, unreadable, or non-JSON input file (`--plan`,
`--orientation`, `--print-rotate`, `profile.json`, `orientations.json`) never produces a
traceback. `units.read_json(path, role)` raises `InputFileError` (a `SystemExit`: stderr gets
`error: <message>`, exit 1). `run_cadquery_model.py` instead emits its normal JSON contract
with an `errors` entry `{type: "file_error", message, hint}`; `quality_gate.py` emits
`passed: false` with a `file_error` issue. STL loaders say "STL not found" vs "not a valid STL".

| Script | Role |
|--------|------|
| `src/run_cadquery_model.py` | Subprocess wrapper: runs a `.py` model (via `run_model_shim.py`), validates geometry, checks DFM constraints, emits structured JSON with `errors` and `geometry` fields. STL paths are hidden during iteration (temp dir); use `--deliver` to get deliverable files (without `--print-rotate` the shim writes them from its own load via `exporters.export_loaded`, so the script runs once; with it, the exporter re-imports the build pose). Sets `PYTHONPATH=<src>` itself so the model can `from blocks import ...`. `--preview` forwards `--auto-sections`/`--extra-section`/`--detail`/`--callout`/`--unlocated-name`/`--feature`/`--sheet` to `render_preview.py` exactly as given. When a script's `result` is a `dict[str, Workplane]` (multi-union), it validates each union body, prefixes each finding's `message` with the union id and carries a `union` field, and aggregates `geometry` over the unions (summed volume/faces, bbox envelope); a single-`Workplane` result is byte-identical to the single-body report. With `--wall-min` set, `geometry` gains `thin_regions` (each with `thickness_mm`, `orientation` of `xy`/`z`, `location_xyz_mm`, `thin_direction`, `nearest_feature`); only XY-thin regions below `wall_min` become blocking `thin_interface` errors, Z-thin slabs are reported but advisory only. `--attempts-log <path> --model <name>` appends this run's attempt record via `telemetry.record_attempt` (part id = script stem, `_stub` scripts skipped, record dropped when `build/<id>_prompt.txt` is absent); the builder prompt always passes it, because the `PostToolUse` telemetry hook does not see sub-agent tool calls and skips any command carrying the flag. Every run is also recorded in script history (`script_history.record_run`, `ok` = `success`, `attempt` when the script's stem is a plan part) unless `CQ_HISTORY_SKIP=1`; the result gains `unmanaged_edit` (`script_history.unmanaged`), which never changes `success`, `errors` or the exit code. |
| `src/run_model_shim.py` | Tiny shim invoked by the wrapper: `runpy`-executes the model script and auto-exports its `result` to STL if the script did not export one itself. A `result` that is a `dict[str, Workplane]` (a multi-union part) is exported one `<union_id>.stl` per key. Before exporting, it runs BRepCheck on every body (each dict value except `keep_out`) and writes `brep_check.json` (`{union_id_or_stem: ["<Solid|Shell|Face|Edge|Vertex>: <BRepCheck status>", ...]}`) in the temp dir; it skips `--deliver` export when any body is invalid. A BRep-valid body then goes through `mesh_gate.mesh_gate_error`; a failure is stored as the single entry `"Mesh: <reason>"`. The wrapper turns each non-empty list into a blocking `invalid_brep` error, or `invalid_mesh` for a `Mesh:` entry (`success: false` with or without `--strict`, `union`-attributed for multi-union parts). |
| `src/mesh_gate.py` | `mesh_gate_error(shape)` -> `None` or a reason string: the CADGenBench validity gate's mesh stage, ported from `cadgenbench/common/mesh.py`. It round-trips the body through STEP (the round trip alone can flip a high-tolerance solid) and sets the deflection to 0.001 x the tolerance-enlarged bbox diagonal, clamped to [0.005, 0.5] mm, escalating through divisors (1, 4, 16, 32). It runs `BRepMesh_IncrementalMesh`, stitches faces by shared-edge polygon node indices and BRep vertices (union-find, no coordinate weld), drops zero-area triangles and cancels opposite-winding duplicate pairs, then requires every edge in exactly 2 triangles, consistent winding and no pinch vertex. It catches BRep-valid solids the welded-STL `watertight` check passes but graders reject (coincident faces from a `clean=False` boolean). Under a second on ordinary parts; 10-30 s on ~600-face imported benchmark parts. |
| `src/cq_verify.py` | Construction-time assertions a generated part script imports (visible on the wrapper's `PYTHONPATH`, like `blocks`): `verify_boolean` (silent no-op cut/union), `verify_feature_bounds` (feature past the base body), `check_workplane` (origin drift after `.center()`/`.hole()`), `verify_stage` (a named construction stage whose bbox/volume doesn't match expectations), `verify_backed` (a feature's mating face, named by a signed axis, not fully backed by a named neighboring feature -- bbox reach + orthogonal-axis containment). Each returns its post-op argument so it chains inline and raises one marked `RuntimeError` (`[cq-verify:<kind>:<label>] ...`) on failure, which `run_cadquery_model.py` maps to a typed `silent_boolean`/`feature_overflow`/`workplane_drift`/`stage_mismatch`/`unbacked_mate` error. CadQuery + stdlib only; not a block, not in `inventory.json`. |
| `src/script_lint.py` | AST-based static pre-flight lint for a generated part script, run by the part loop's Step 2.5 before the first `run_cadquery_model.py` call. Stdlib `ast` + `json` only, no CadQuery import. Detects `boolean_in_loop`, `missing_result`, `submodule_import`, `direct_export`, `magic_number` (numeric literal in a `cq.Workplane`-rooted fluent chain, exempting named top-level parameters and the common-angle/index literal set), `unanchored_feature` (a placement call after an unre-anchored `.center()`/`.hole()`), `unguarded_boolean` (a `.cut()`/`.union()` on a computed-offset tool not wrapped in `verify_boolean`), `shell_after_fillet`, and `fillet_after_chamfer` (a `.fillet(...)` after an earlier `.chamfer(...)` in the same chain). Findings share the wrapper's `{type, message, hint}` shape plus `line`. CLI: `python script_lint.py <script.py>` prints `{"success": bool, "findings": [...]}`, exit 0 clean / 1 findings. A syntax error becomes a single `syntax_error` finding instead of raising. **Step form**: when the script builds through `blocks.Part` (or under `--step`, which the builder always passes) it also reports `raw_cadquery` (any `import cadquery`, `cq.*` call or Workplane method, with a hint naming the closest primitive) and `script_dimension` (a `# PARAMETERS` block or any argument to `resize` beyond the handle), and skips `magic_number` (sizes are plan-owned). |
| `src/script_history.py` | Per-script source history (stdlib only). `record_run(script, ok, *, attempt=None, suppressed=None)` stores the source as `build/history/<stem>/<sha12>.py` (once) and appends a `run` event to `build/history/<stem>/log.jsonl`; called by `step_worker.py run` and `run_cadquery_model.py` (`_emit`), skipped when `CQ_HISTORY_SKIP=1` (the step worker's full tier, the quality gate's wrapper run, the test suite), and never raises (a failure prints one `[cq-design:history]` stderr line). CLI: `restore <target> <script>` rewrites the script from `@last_ok` (latest `ok`, unsuppressed run), `@prev` (latest recorded source differing from the current file), `@<hex prefix>` (4+ chars, unique) or a mark name, logs a `restore` event (with the replaced source's hash, stored first) and, when `<stem>.steps.jsonl` exists, a step-worker `restore` event there; `warning: attempt_mismatch` with `attempts: {source, current}` when the source ran at another plan revision. `mark <name> <script>` records a named baseline (`@` names rejected). `record_command` logs a `script_ops.py` write as a `command` event; `unmanaged(script)` is true when the log has a `command`/`restore` event and the current source matches none of their hashes. One JSON object out; exit 0 on success, 1 otherwise. Not bundled into `lib/`. |
| `src/script_ops.py` | Group commands, the only way an LLM changes a part or edit script (stdlib `ast`; reuses `script_lint.lint_script`). Layout: a script using `Part` is a header, one group per plan instance (from its `select(..., id=X)` to the next `select`; an `if part.has("X"):` block is group `X`) and a tail (a final top-level `result = ...`); a script with `# step: <name>` lines is a header plus one group per section, no tail; anything else is one group `whole`. Groups end at their last statement, so a trailing comment in a code file joins the next group. CLI: `list`, `show <id>`, `new (--template <file> \| --code <file>) [--force]` (template copy sets `Part("<stem>")`), `replace <id> --code <file>`, `insert (--after <id> \| --first) --code <file>`, `remove <id>`, `move <id> (--after <id> \| --first)`; code only from a file. Preflight on the candidate, first failure refuses with the file byte-identical: `parse_error`, `group_identity` (code is not exactly the addressed group / reuses an id), `scope_violation` (header, tail, order or any other group's text differs), `undefined_local` (a region reads a top-level name no earlier region or itself assigns), `unknown_instance` (step scripts: addressed id not a `blocks_needed` instance of the `Part` id in `CQ_PLAN` or the nearest `BUILD_PLAN.json`), then `script_lint.py --step` findings (step scripts only: edit scripts are raw CadQuery). Applied commands are written atomically and logged via `script_history.record_command`. One JSON object (`success`, `command`, `group`, `changed_groups`, `errors`, `src`); exit 0 / 1. Not bundled into `lib/`. |
| `src/plan_params.py` | Resolves string values in `blocks_needed[].params` as expressions over numeric `parameters.py` constants (read with `ast`, never imported). Allowed: numbers, constant names, `+ - * / //`, unary minus, parentheses, `min`/`max`/`round`; anything else raises `PlanParamError`. `plan.py validate` reports expression errors, writes `build/params_resolved.json` (part -> hash of resolved params) and prints `Resolved params changed for: <parts>` against the previous run; `blocks.Part` resolves on load (so `Part.param` is numeric); bundled in `lib/` and by `export_standalone.py`. `quality_gate` advisories: `parameters_untagged` (constant without a `# user`/`# researched`/`# assumed`/`# design choice` comment), `parameter_literal_duplicates_constant`. |
| `src/concept_sketch.py` | `concept_sketch.py <concept.json> [--out concept.svg]`: Phase 1 concept sketch. JSON `{title, shapes[{view,type: rect\|circle\|line\|polyline,...}], labels[], dims[]}` with `view` front\|top\|side, mm, y up. Prints `{"out"}` (exit 0) or `{"error"}` (exit 1: unknown shape/view, missing field). Stdlib only. |
| `src/probes.py` | Probe kinds evaluated on the BRep, no mesh: `solid_at(p)`/`empty_at(p)` (`BRepClass3d_SolidClassifier`; compounds: IN if any solid), `ray(p, dir, hits, length)` (face crossings on the line or a centered segment), `bbox(lo, hi, tol)` or `bbox(size=..., mode="within"|"exact")`, `delta(sign)`. `Registry` holds probes with an owner (`"plan"` or a step index); `retire_inside(tool)` retires block probes inside a later tool, never plan probes; `check(shape, final, armed)` arms a plan feature probe once its interface `instance` is placed (no instance: only `final`). `plan_probes(part)` seeds the envelope (`within`, exact at `result()`) and, from the `CUT_TYPES`/`THROUGH_TYPES`/`BOSS_TYPES` table, `empty_at` (+ `ray` along the wall axis for through types) or `solid_at` per interface with `position_mm` and a size; others go to `unprobed_interfaces`. It then appends the part's authored `probes[]` entries unchanged (`Probe(**entry)`, lists as tuples; kinds `solid_at`/`empty_at`/`ray`/`bbox`, required `label`, optional `instance`; `delta` is rejected by the schema, and `plan.py validate` checks `instance` against `blocks_needed` ids). Authored probes are plan-owned like interface probes: same arming, never retired, part of the `Part` step key; legacy part scripts do not evaluate them. CLI: `python probes.py plan BUILD_PLAN.json --part <id>` prints `{part_id, probes, unprobed_interfaces}`. |
| `src/blocks/imported.py` | `import_solid(path, max_volume_deviation=0.01)` (re-exported from `blocks`): imports `.step`/`.stp`/`.brep` and checks it (BRepCheck valid and no face below 1e-3 mm2). An invalid import goes through a cumulative repair ladder, checked after each rung: `drop_slivers` (remove sub-1e-3 mm2 faces, sew at 1e-2), `defeature` (BRepAlgoAPI_Defeaturing of BRepCheck-flagged faces; counted only when it actually deletes one), `patch` (replace flagged faces with a MakeFilling patch, sew). No tolerance-only fixes (STEP export drops them). A rung result must also pass `mesh_gate.mesh_gate_error` (a valid import skips it). The first rung result that passes within the volume limit (fractional, vs. the imported volume) is returned and reported as one stdout line `[cq-design:step-repair] {"file", "strategy", "faces_removed", "volume_delta_pct"}`; otherwise it raises `[cq-verify:step_unrepairable:<file name>]`, which the wrapper maps to a `step_unrepairable` typed error. `brep_statuses(shape)` is the shared status walk the shim uses. Defeaturing can take minutes on ~1k-face parts, hence `--timeout 600` in the edit command. |
| `src/blocks/part.py` | `Part(part_id)` step recorder (re-exported from `blocks`): finds `BUILD_PLAN.json` via `CQ_PLAN` or by walking up from the script. `select(name, id)` binds an inventory entry to a `blocks_needed` instance; `resize(h)` builds it from the instance `params` (a `print_up: "auto"` value resolves to `print_up()`) and checks the entry's own probes; `place(h, at, rotate, op, into, member)` (`at` one point or a list; `rotate` degrees about X, then Y, then Z; `member` for a pair block) checks volume sign, one solid per body and the whole registry; `param`, `positions`, `has` read the plan; `result()` checks the exact envelope and, under `CQ_PRINT_ROTATE`, applies each instance's plan `edges` (fillet vertical/diagonal, chamfer horizontal in print pose), then re-checks plan probes. Failures raise `[cq-verify:step_plan|probe_failed|finishing_probe_failed:step<i>:<entry>]` markers that `run_cadquery_model.py` types. `Part.cache` (set by the step worker) reuses step results keyed by a hash chained over the plan probes and each step's resolved args and entry source. |
| `src/step_worker.py` | Warm worker for step scripts. `run <script> [-- <run_cadquery_model.py args>] [--no-full]` prints `{success, part_id, steps, failed_step, failing_probes, diff_vs_last_good: {last_good, failed}, probe_stuck, stuck_occurrences, unprobed_interfaces, error, worker: "warm"|"fallback", full}`; `full` is the `run_cadquery_model.py` result, run only when every step passed. One worker per build dir (`multiprocessing.connection` on 127.0.0.1, authkey; `<build>/.step_worker.json`), started on demand, idle timeout 600 s; a dead or timed-out worker is killed and the request re-run cold in a subprocess. `snapshot save|restore <name> <script>` / `snapshot compare <a> <b> <script>` keep builder-only snapshots in `<build>/snapshots/<part>/` (BRep, script source, registry); restore rewrites the script. `run --suppress <instance_id>` (repeatable) runs without that plan instance's `select`/`resize`/`place` steps (recorded with `suppressed: true`, no key-chain advance so toggling stays cache-warm, no probes armed; unknown id = `step_plan` error); the report lists `suppressed`, the full tier is skipped (`full: null`). The report also carries `attempt` (plan revision). Each `run` is recorded once in script history (`script_history.record_run`, `ok` = steps and full tier passed; the full-tier subprocess gets `CQ_HISTORY_SKIP=1`). The report carries `unmanaged_edit` (script changed outside `script_ops.py`; advisory). Every run appends a `run` event, and every probe failure a `fail` event, to `<build>/<part>.steps.jsonl`; a probe failing again after a `restore` event or a changed failing step sets `probe_stuck`. |
| `src/units.py` | Shared part->unions expansion (no CadQuery import). `is_copy(part)` is true for a part declaring `copy_of` (`{part, mirror?}`): it has no script; `write_assembly.load_part_unions` reads the source part's script, reflects it across the plane normal to `mirror` when given, and exports it under the copy's own id/placement; its manifest entry carries `script_part` (the source stem) so the staleness checks (`freshness.script_stem`) hash the source script. `iter_unions(plan)` yields `(part, union_id, plate)` for every union (`plate_of`: union `plate`, else part `plate`, else union `object`, else union id); `union_entries(plan)` maps union id -> its declared `unions[]` entry (`{id}` for an implicit union) and `object_groups(plan)` maps `object` id -> member union ids; `resolve_unions(part, result)` normalizes a script's `result` (a `Workplane` -> one union id=part id, or a `dict[str, Workplane]` -> one per key, keys validated against declared `unions`), ignoring the reserved `keep_out` key. `resolve_keep_out(part, result)` extracts that reserved key's `name -> Workplane` mapping of author-declared keep-out zones (never itself a union); `keep_out_stl_name(part_id, zone_name)` is the shared writer/reader STL naming convention. `iter_kinematics_entries(kinematics)` flattens the `kinematics` tree (entries nest via `children`), depth-first; also used to collect one entry's own swept subtree via `iter_kinematics_entries([entry])`. The one place that knows a part may produce several unions (or zones); used by `write_assembly`, `plan_validate`, `kinematic_check`, `plate_clearance_check`, `keep_out_check`, `build_template`. |
| `src/quality_gate.py` | Aggregates wrapper DFM + in-process trimesh geometry/overhang analysis (watertightness, overhang area/worst-angle/location vs `overhang_max_deg`; connected overhang regions that are near-horizontal, at most `constraints.bridge_max_mm` (default 10) across and supported on two or more sides are bridges, reported as an `info` `bridges_detected` issue with `bridge_area_mm2` and excluded from `overhang_exceeded`; `mesh_io.overhang_metrics` adds `bridge_area_mm2`/`bridge_count`); a `sliver_fin` `warning` (`fold_count`, `sharpest_interior_deg`, up to 5 print-pose `locations_xyz_mm`, `min_face_area_mm2`) when `mesh_io.fold_metrics` finds adjacent triangles with an interior dihedral under 10 degrees -- zero-thickness fins/knife edges that survive a valid, watertight mesh and that slicers draw as spikes; a `brim_recommended` `warning` (`contact_area_mm2`, `height_ratio`) when the print-pose bed contact (`mesh_io.bed_contact_mask`) is under `mesh_io.BRIM_MIN_CONTACT_MM2` (50) or height/sqrt(contact) exceeds `BRIM_MAX_HEIGHT_RATIO` (6); a `vertical_feature_below_layer` `warning` (`min_gap_mm`, `layer_height_mm`) when `mesh_io.min_horizontal_gap` finds two horizontal face planes (merged within 1e-3 mm) closer than the layer height (profile.json `motion.layer_height_mm`, else `nozzle_mm * 0.5`). Both are advisory, never blocking. No slicer or MCP required. Also runs the kinematic, plate-clearance, keep-out-zone, edge-treatment (chamfer/fillet), cosmetic-slope (visual_quality-only, advisory), and telemetry-presence stages once outside the fix loop. The telemetry-presence stage warns (`source: "telemetry"`, `type: "telemetry_missing"`, never blocking) when `attempts.jsonl` is absent, empty, or has no parseable JSON line -- default path is `attempts.jsonl` alongside `--script`, overridable via `--attempts-log`. Report-only by default (`allow_fix=False`); emits structured report and print recipe on clean pass. Opt-in `--fix` invokes `claude -p` for targeted fixes (up to 2 rounds) via a cold-context subprocess -- for standalone use outside the skill pipeline, which instead routes gate findings into the part loop's own fix path (`skill/phase3_build.md`). Sets `PYTHONPATH=<src>` itself. Real slicer-based printability validation (e.g. the orca-check MCP) is optional and external, not part of the gate. `--previous <report.json>` adds `delta: {resolved, regressed}`, each a list of `{type, union, source}` identities of `fix`/`re_export` findings present only in the previous / only in this report (messages excluded: they carry measured numbers); an unreadable previous report is a `file_error` report, exit 1. Its wrapper run sets `CQ_HISTORY_SKIP=1`. |
| `src/plan.py` | One CLI over `BUILD_PLAN.json` with three subcommands. **`validate <plan>`** -- Validates `BUILD_PLAN.json` against JSON Schema draft-7; cross-checks `blocks_needed` against `blocks/inventory.json`, a present per-part `archetype` against `templates/archetypes.json` names, part `placement` rotation axes, union-id uniqueness across the model (a part's declared `unions`, else its id), `kinematics` entries at every nesting depth of their `children` tree (`moving_union` is a **union** id; when the entry names a `block`, it exists, carries a `dof`, and the joint contract type/axis is satisfied -- a block-less entry skips the contract, its axis and range being author-declared), `joints` entries (members reference the block's declared `emits` ids and existing parts; poses derive along a BFS spanning tree from `root_part`; a loop-closing joint is allowed only when every joint on the loop is rigid (block has no `dof`) and its docks close within 0.01 mm / 0.01 deg, otherwise it is a conflicting mate path; unanchored and double-anchored parts are also caught), `request_log`'s exactly-one-`initial`-first constraint (draft-7 cannot express this in the schema), and every `bom[].parts` entry against `parts[].id` (`_check_bom_parts`, hard error on an unknown id). Since `placement` is supplied by the part author during the build phase, the joint-contract axis arm skips its comparison -- rather than wrongly treating an absent placement as identity -- for any kinematics entry whose moving union's part has no `placement` yet; `check_deferred_axis_arms(plan)` reports those entries as a non-fatal advisory (printed by `main()` alongside `check_block_thinness` findings). `check_bom_coverage(plan, inventory_path)` is a second advisory, printed as "BOM findings": a part using a block with `blocks/inventory.json`'s `supplied_hardware` set (e.g. `heat_set_boss`) while no `bom` row lists that part id -- not fatal, since the hardware may legitimately be listed under a sibling part. The Phase 3 part loop re-runs `plan.py validate` after every part's placement write-back and before `write_assembly.py`; that run is authoritative for the axis arm and any other placement-consuming check, and a failure blocks export. **`summary <plan>`** -- prints the Phase 2 checkpoint as Markdown (absolute plan path, printer/material/nozzle, parts with dims/load/pose/blocks/archetype, print optimization with overrides and `show_face`, review policy and its meaning, interfaces, a **Materials** table (union, material, color, filament slot) when unions resolve to more than one material+color, with a `WARNING: N materials, M slots` line when N exceeds the profile's `max_materials` (`--profile`, default `profile.json` beside the plan, absent = 1), a **Non-printed hardware** table from `bom` when non-empty, constraints); assumes a validated plan. **`import-params <script.py> --part <id> [--plan BUILD_PLAN.json] [--write]`** -- Reconciles a hand-edited part script's `PARAMETERS` block back into `BUILD_PLAN.json`. `parse_parameters(script_path)` statically extracts module-level numeric-literal assignments via `ast` (no import, no CadQuery, bools excluded); `reconcile(parsed, plan, part_id)` maps the fixed conventional names `width`/`depth`/`height` -> `dimensions.{w_mm,d_mm,h_mm}` and diffs against the plan, collecting anything else as `unmapped` advisory. Default is a dry run; `--write` applies the diff to a deep copy, re-validates via `validate_plan` (against a temp file), and persists only on a clean pass. CLI: `python plan.py import-params <script.py> --part <id> [--plan BUILD_PLAN.json] [--write]`; emits `{part, changed, unchanged, unmapped, written, errors}` JSON, exit 0 clean / 1 on error or refused write. `validate` also checks each `blocks_needed` instance object: unique `id`; `params` names only params its inventory entry declares and includes every non-`optional` one; `edges` names only the entry's `edge_sets`; every interface `instance` names a planned id. `import-params` on a step script (uses `Part(`, no `# PARAMETERS`) returns `status: "not_applicable"`, writes nothing, exit 0. |
| `src/printer_profile_validate.py` | Validates `profile.json` against `src/printer_profile_schema.json` (`validate_profile`); `write_profile_fields` merges a partial field update (e.g. an override the user stated for one model) into the file and re-validates before writing. CLI: `python printer_profile_validate.py profile.json` to validate, `--set field=value` (dotted for `constraints.*`) to write back. |
| `src/placement.py` | Shared assembly-pose placement helper: builds a 4x4 transform (`to_matrix`, for trimesh/3MF) and positions a CadQuery Workplane (`apply_cq`) from a part `placement` (ordered X/Y/Z rotations through origin, then translation), or from a general 4x4 transform (`apply_matrix`, for a derived mate-chain pose that doesn't decompose back into the ordered-rotation shape). Identity when absent. |
| `src/mate_chain.py` | Derives a mated part's assembly pose from `BUILD_PLAN.json`'s `joints` + `root_part`: `compute_mate_poses(plan)` walks the mate chain outward from `root_part`, composing `world_pose(part_B) = world_pose(part_A) @ dock_A @ inverse(dock_B)` at each hop (both members of a matched-pair block share one local frame with exactly one embedding into the assembly pose, so this is exact, not solved for). Returns `{part_id: 4x4 transform}` for every non-root part reached via a joint; trusts `plan_validate`'s mate-graph tree check (no cycle handling here). |
| `src/write_assembly.py` | Assembly writer: loads each part's `result`, splits it into unions via `units.resolve_unions` (a part may declare `unions` and return a `dict[str, Workplane]`; default is one union id=part id), applies the part's `placement` to each union -- or, for a part reached via a `joints` mate chain, its derived pose from `mate_chain.compute_mate_poses` instead (`pose_union`) -- and writes one assembled-pose STL per union (the kinematic / plate-clearance checks' input) into `stl_dir`. Also extracts any declared keep-out zones (`units.resolve_keep_out`), poses each the same way as its declaring part's unions, and writes one assembled-pose STL per zone (`units.keep_out_stl_name`), returned as `keep_out_stls`. Also writes `stl_dir/export_manifest.json` (`freshness.write_manifest`) recording each union's and zone's provenance stamp and `print_rotate`, returned as `manifest`. Writes nothing user-facing. `assemble(plan, parts_dir, orientations, progress)` is the shared loader (also used by `deliverables.py`); `write_assembly(..., progress=None)` takes an optional keyword-only callback receiving `[k/N] loading <id>` and `[k/N] stl <union>` lines; `None` is silent and never changes the output. CLI: `--plan`, `--parts-dir`, `--out` (the STL dir), `--orientations`; prints a JSON result. A step script's finishing pass failing (`finishing_probe_failed`) makes the CLI print `{success: false, errors: [{type, label, message, hint, action: "ask_user"}]}` and exit 1. |

| `src/preview.py` | Headless preview renderer using CadQuery tessellation + the numpy z-buffer rasterizer `src/zbuffer.py` (per-pixel depth test, orthographic views incl. the isometric panel) -> multi-view PNG. Every panel draws silhouette/depth-discontinuity edge lines (`zbuffer.edge_mask` on `zbuffer.rasterize_with_depth`). `render_section`/`render_detail_section` colour the cap (triangles on the cut plane) distinctly with an outline and return a `SectionPath` (a `str` with `.informative`: false when the cap equals the uncut silhouette and has no inner hole). No OpenGL or display server required. The default 2x2 tile's three orthographic panels are labeled with the compass viewing station ("Viewed from South/West/above", `preview.MULTI_VIEW_PANELS`), verified against an asymmetric fixture, not left/right/front/back. `render_multi_view` accepts optional `callouts` (`{"name", "center"}` per feature, build pose): projects each through the panel's camera (`zbuffer.make_camera`) and draws a numbered badge + leader line on the first panel (ortho panels in tile order, then isometric) where a z-buffer visibility test shows the anchor unoccluded; badges within 12 px merge (legend `NAME xN`), a callout visible in no panel is legended `NAME (hidden)`; a caption legend line maps badges to names; `unlocated_names` lists named features with no known position as unbadged "(not located)" legend entries. Feature previews: `render_feature_view`/`render_feature_section` take a `feature_frame` frame and an anchor; the camera looks along the frame normal (opposite side, then isometric, when the z-buffer shows the anchor occluded), framed on the bbox, with the callout badge drawn at the projected anchor (`render_detail_view`/`render_detail_section` take the same optional `marker=`); the section plane contains the normal and the longer in-plane axis at the bbox centre, and is skipped when `depth_mm < 0.5`. `render_sheet(tiles, path, title, not_shown, not_located)` composes at most 4 `(image, caption)` tiles into a 2 x 2 PNG (extra tiles, `not_shown` and `not_located` names are listed in the footer as `NAME (not shown)` / `NAME (not located)`; see `sheet_legend`). |
| `src/render_preview.py` | Subprocess entry point for previews: runs a model script in an isolated namespace, captures `result`, calls `preview.render_multi_view`/`render_single`. Accepts repeated `--callout "name=<n>;center=x,y,z"` (multi view only, reuses `--detail`'s spec-parsing conventions) and `--unlocated-name <name>`, forwarded to `render_multi_view`. Section files are printed as `Detail preview saved: <path> (informative: true|false)` (advisory, not a gate); the trailing JSON `extra_previews` list is unchanged. Accepts repeated `--feature "name=<n>;center=x,y,z[;diameter=<mm>|;size=<w>,<h>][;section=AXIS=MM]"` (frame derived per feature by `feature_frame.py`; writes `<stem>_feature_<name>.png` and, with depth, `<stem>_feature_<name>_section.png`; a feature with no frame is `(not located)` and its `section=` guess becomes an ordinary `--extra-section`-style cut) and `--sheet` (writes `<stem>_sheet.png`, listed first among the extra previews: `--feature` tiles in supply order, then whole-part sections, 4 tiles max; features beyond the cap are not rendered and are legended `(not shown)`). `--auto-sections` now fills slots after the bore/boss cuts with up to 2 slice-scored cuts (`section_select.score_slices`). `run_cadquery_model.py` forwards `--feature` and `--sheet`. |
| `src/section_select.py` | Geometry-driven section selection: `select_sections(shape, max_cuts=3, reserved=())` finds axis-aligned cylinder/cone faces (angular coverage >= 0.5, radius >= 0.5 mm, coaxial faces merged into one `stepped` feature) and greedily picks up to `max_cuts` planes containing their axes, weighted by radius x length; cuts within 0.5 mm of a `reserved` cut are dropped. CLI `python section_select.py <script> [--max N] [--reserve AXIS=MM]...` prints `{"sections": [{axis, position_mm, features}], "extra_section_args": [...]}`; exit 1 if the script does not load. `render_preview.py --auto-sections` (implies `--cross-sections`; forwarded by `run_cadquery_model.py --preview --auto-sections`; always in the builder's validate command) calls it on the compound of every union with the `--extra-section` cuts as `reserved` and appends its cuts after them, up to 3 total, named `<stem>_section_<axis>_<pos>mm.png`; bbox-center cuts remain the fallback when there is no cut; a selector error only prints a `WARNING`. `score_slices(shape, reserved=(), max_cuts=2, time_cap_s=5)` samples 15 planes per axis, scores each slice as inner loops + 2 x void fraction (per section face against its own bbox) + area change vs neighbouring slices, keeps the best slice per axis at or above 1.2, drops any within 0.5 mm of a reserved cut, and returns `[{axis, position_mm, score}]`; when the time cap runs out it returns what it has (possibly `[]`, so the bbox-centre fallback stays). |
| `src/feature_frame.py` | Solid-derived feature frame: `feature_frame(shape, position, diameter_mm=None, size_mm=None)` collects faces whose bbox meets a cube of radius `max(diameter_mm, max(size_mm), 2)` around `position`, treats faces spanning more than twice that radius as the host wall (excluded from the bbox), and returns `{located, bbox: {min, max}, center, axis, normal, depth_mm}` or `None` (feature "not located"). The normal axis is the host wall's (nearest axis-aligned planar host face to `position`, larger area breaking ties), else the remaining faces' area-dominant axis; its sign points from the part centre toward `position`; `depth_mm` is the bbox extent along it (features with `depth_mm < 0.5` get no section). CLI `python feature_frame.py <script> --center x,y,z [--diameter D] [--size W,H]` prints the frame JSON, or `{"located": false}`; exit 1 if the script does not load. |
| `src/mesh_io.py` | Thin trimesh loader with watertightness validation. ## render_prompt.py

Prints `{"out", "chars", "model", "agent_model"[, ...kind extras]}` for every kind. `model` is the full id from `skill_config.json` (else the shipped default) and is what logs record. `agent_model` is the Agent-tool alias derived from it (first of `fable`, `opus`, `sonnet`, `haiku` found in the id, else the id unchanged); every spawn passes it as the Agent tool's `model`, because hosts may ignore the agent file's `model:`.
