# Evals

Developer-only eval harness; not shipped with the installed skill.

| Script | Role |
|--------|------|
| `evals/run_evals.py` | Eval harness over the canonical corpus in `evals/cases/` (~10 requests, each with `request.md`, golden `BUILD_PLAN.json`, golden meshes, `case.json`). Default mode scores an existing run dir (no model calls): first-shot rate + attempts-to-pass + cost per accepted part, Chamfer distance (point-to-surface, bbox-center aligned; needs `rtree`) against the golden meshes. Produced solids are enumerated from the run's `stl/*.stl` (excluding `plate_*.stl`/`keep_out__*.stl`, per `write_assembly`'s naming contract) and matched to golden meshes by a one-to-one geometric assignment (sorted bbox extents + volume cost, `scipy.optimize.linear_sum_assignment`) rather than by part id; an unmatched golden part fails `within_tolerance`, and a run with no produced solids is reported as a distinct `no_artifacts` state. Emits `scorecard.json`/`scorecard.md`, including how many cases contributed to the mean Chamfer. Per-case cost prefers a billed number when recorded -- `<case>/cost.json` (the `claude -p --output-format json` envelope captured by `--generate`), else `<case>/build/cost.json` (the `session_cost.py` record's `combined.cost_usd`) -- and falls back to a `prompt_chars / 4` estimate from `build/attempts.jsonl` and `src/model_prices.json` (input rate only); the scorecard's `cost_source` / `cost src` column reports which was used. `src/model_prices.json` entries are `{input, output}` USD/MTok. `--generate` (opt-in, costs tokens) runs `claude -p` per case first and writes `<case>/cost.json` from the result envelope (nothing written on timeout or unparseable output). `evals/generate_goldens.py` regenerates the golden STLs. |
| `evals/cadprompt_bench.py` | External benchmark against CADPrompt (github.com/Kamel773/CAD_Code_Generation, arXiv 2410.05340). The upstream repo has no license, so nothing from it is vendored: `--dataset` points at a local, manually-downloaded copy of its `CADPrompt/` folder, and the script should be run with `python -I` (it only parses the dataset's `Ground_Truth.stl` files, never executes its code). `SELECTION` holds 10 prompt ids across the four "Semantic complexity" tiers of `Data_Stratification.xlsx`. Each id has a committed part script `evals/cadprompt/parts/p<id>.py`, written from that prompt's `..._with_specific_measurements.txt`; the harness delivers it with `run_cadquery_model.py --deliver --formats stl --output-dir <out>/<id>` (no model calls) and scores the STL against `<dataset>/<id>/Ground_Truth.stl`. Scoring follows the paper: both meshes are bbox-centered and scaled to a unit cube by their largest extent, and the produced mesh is rigidly ICP-aligned (no scale, no reflection) onto the ground truth. ICP is seeded from all 24 axis-aligned rotations and the lowest-cost result is kept, which goes beyond the paper's identity seed. The metrics are Chamfer distance (mean of both directed mean nearest-neighbour distances over 2048 seeded surface samples; about 0.01-0.02 for an exact match) and volumetric IoU (`contains` on a 48^3 grid over the union bbox). A missing script or a failed build scores Chamfer sqrt(3) and IoU 0. CLI: `--dataset`, `--out` (required). Prints a markdown table with per-prompt rows plus per-tier and overall means (built count, Chamfer, IoU) and writes `<out>/cadprompt_scores.json` (a list of `{id, tier, built, chamfer, iou}`). The recorded run is `evals/cadprompt/sample_run.md`. |
| `evals/cadgenbench_run.py` | Runs cq-design against the public [CADGenBench](https://huggingface.co/spaces/HuggingAI4Engineering/CADGenBench) inputs and builds a submission zip; no local scoring (the ground truth is private, so the Space scores the uploaded zip). Fetches `HuggingAI4Engineering/cadgenbench-data` over plain HTTPS at the commit it resolves (written to `<data-dir>/REVISION`); per fixture runs `claude -p` (costs tokens; an edit fixture, one with `edit_description.txt`, is prompted as `/cq-design:edit input.step <description>`, other fixtures with the drawing-reproduction prompt) in `<run>/_work/<id>/` with an explicit `--allowedTools` allowlist and `--permission-mode acceptEdits` (never `--dangerously-skip-permissions`), writing `cost.json` from the result envelope, and stops generating at the first usage-limit error (`LIMIT_MARKERS`; a rerun resumes); takes the delivered STEP(s) from `out/` (else `build/`), fuses them, moves them into the benchmark's canonical pose (bbox centre at the origin, Lx >= Ly >= Lz, proper rotation only; the optional mounting-face rule is not applied), and writes `<run>/<id>/output.step`. Then runs the dataset's `sanity_check_submission.py` on each candidate in an isolated `uv run --with cadgenbench@<CADGENBENCH_REF>` env (Python 3.12; the grader image's commit, plus `SANITY_PINS`: `cadquery-ocp-novtk<8` because OCP 8.0.1.1 breaks its STEP load, and the grader's `pyvista==0.48.4`) into `<run>/sanity.json`, and writes `<run>.zip` with `meta.json` plus one folder per fixture (an empty folder when there is no candidate, which the Space scores 0). `agree_to_publish` is always written `false`; the Space rejects that, so flip it by hand before uploading. Flags: `--fixtures`, `--force`, `--skip-generate`, `--timeout`, `--submitter`, `--name`, `--agent-url`, `--notes`. |
